# 扩展（Extensions）

侧栏「扩展」页管理 EZ Switch 内置的协议扩展。扩展随应用一起内置，不需要下载扩展或访问插件市场。

当前内置的扩展有两项，各自有独立的总开关与独立卡片，互不影响：

1. **Chat → Responses 转换**（下称“转换”）：让只提供 Chat Completions 的上游也能服务 Codex 等客户端发出的 `/v1/responses` 请求。它是纯内置扩展，不需要任何外部依赖。
2. **出站代理**：让所选原生供应商（以及将来注册的连接器）的出站请求经同一个 HTTP / SOCKS 代理，见下文。

「扩展」页每个扩展是一张独立的**纵向可折叠卡片**：标题栏含图标、名称、简短摘要与自己的总开关，展开体里才是该扩展的设置与名单。各扩展的供应商/来源名单都放在**其所属卡片内**，不跨卡片混排。

下面先完整说明 Chat → Responses 转换，再说明出站代理。

> 通用连接器框架仍在宿主中保留（见[扩展架构与移除说明](extension-architecture.md)），但当前**没有内置连接器**，因此扩展页不会再出现连接器卡片。

## Chat → Responses 转换

默认情况下，本机按原协议把 `/v1/responses` 原生转发给上游。当上游只支持 Chat Completions 时，开启转换后：

- 客户端仍请求本机 `/v1/responses`；
- 应用用内置转换器把 Responses 请求体转换为 Chat Completions 请求，发往所选供应商的 Chat Completions 地址；
- 再把上游返回的 Chat 响应转换回 Responses 格式交给客户端。

转换**按供应商生效，不按模型设置**。同一供应商下的所有模型共用同一条转换规则，不能只对单个模型单独开启或关闭。

## 生效规则

转换只在其条件同时满足时才对该供应商的模型生效：

1. 「扩展」页的扩展总开关已开启；
2. 该供应商在供应商名单中已被勾选。

任一条件不满足，或该供应商没有勾选，则该供应商的模型保持原生 Responses 转发（当该供应商启用了原生 Responses 时）。

总开关与名单相互独立：关闭总开关不会清除已有的勾选，名单在选择状态下仍可编辑；重新开启总开关后，之前勾选的供应商仍然处于勾选状态。

## 界面（Chat → Responses）

- 「扩展」页是独立的侧栏入口；「供应商与路由」页的布局与操作保持不变。
- 页面顶部是扩展总开关，用于整体开启或关闭转换。
- 总开关下方是供应商名单，逐供应商勾选是否参与转换；配置不可用时，在该行显示原因。
- 原生地址、凭据与各协议的启用开关都不受转换影响：转换复用所选供应商已配置的 Chat Completions 地址与凭据，不会覆写、改写或复制原生 Responses 的 Base URL、API Key 或协议开关。

### 缺少 Chat Completions 的供应商

如果某个供应商没有启用 Chat Completions，它就无法作为转换目标：

- 该供应商不能被新勾选（勾选项不可用），名单中会说明原因；
- 若它此前已被勾选、之后又不具备 Chat Completions 配置，仍可取消勾选，界面会用醒目标注说明原因；
- 应用不会把它静默退回原生，也不会留下“已勾选但实际不转换”的模糊状态。

### 供应商身份与生命周期

扩展名单以**供应商名**作为身份（当前供应商没有独立 UUID），并由配置存储随供应商生命周期统一维护，不单独引入一套扩展生命周期：

- 取消勾选或删除供应商：按集中规则清理对应选择，不留下指向已删除供应商的悬空引用；
- 重新添加同名供应商：不会自动继承此前的勾选（不做幽灵继承）；
- 新添加的供应商：默认不勾选，需要手动勾选才会参与转换；
- 重命名供应商会更换其名称标识，其勾选由同一套存储生命周期规则处理，不会静默指向不再存在的旧名称。

## Chat → Responses 的旧配置迁移

在早期版本中，“转发到 Chat”是供应商级别的 Responses 传输方式设置（`responsesTransport`，在内部会随每个模型复制一份，只允许在供应商设置里修改）。升级后该设置迁移为本文档描述的按供应商规则：

- 只要某供应商此前的任一模型使用了 Chat 转换，迁移后该供应商在扩展名单中即视为已勾选，且扩展总开关被打开，其全部模型统一按同一规则处理；
- 迁移只用于兼容读取旧配置并转换为新规则，**不会改写原生 Responses 地址、凭据或其他协议开关**；
- 迁移只影响 Responses 的传输方式，不改动模型列表、路由、自动回退或用量数据；
- 迁移只在配置中尚无扩展字段时执行一次：一旦配置写入了扩展字段，就以已保存的扩展设置为准，不会因重新加载又按旧的 `responsesTransport` 打开转换。

> 迁移只保证对旧配置的 decode 兼容，不提供把新规则反向写回旧字段的路径。

## Chat → Responses 的限制

- 转换要求客户端发送完整会话历史。请求中如出现 `previous_response_id`、`conversation`，或服务端压缩（`compaction_trigger` / `compaction` 项），会被明确拒绝并返回客户端错误，请改用本地压缩；不会静默降级或改用其他方式。
- 转换并非无损，部分 Responses 能力无法在 Chat Completions 中完整表达。
- 转换由随应用内置的独立 helper 进程执行，每个请求一个进程，进程之间不共享状态；API Key 与网络连接保留在应用本体，helper 只接收请求体。
- 用量与性能以**原始上游响应**为准，转换补出的事件不参与统计，详见[用量统计说明](token-usage.md)。

## 出站代理

「扩展」页的 **出站代理** 卡片让所选来源的出站请求统一走一个代理。默认关闭，关闭时不启用任何代理。

- **地址**：一条代理地址，scheme 支持 `http` / `https` / `socks5`，必须带显式端口。首版**不支持**代理认证与 PAC：带用户名/密码（userinfo）、路径、query 或 fragment 的地址会被拒绝。地址由卡片内的「保存」按钮提交（失焦不反复保存）。
- **名单**：卡片内列出**原生供应商**（按供应商名勾选），并在有连接器注册时列出**已注册连接器**（按来源 `source` 勾选）。连接器来源以稳定的 `source` 为身份，登录、添加供应商前即可勾选；连接器自身声明是否支持出站代理，不支持的禁止新勾选，已勾选的仍可取消。当前没有内置连接器，所以实际只列出原生供应商；来源选择能力保留给将来注册的扩展。
- **谁走代理**：只作用于被勾选的原生供应商与连接器来源。**总开关关闭、或某个来源未被勾选时是严格直连**——绕开 macOS 系统代理，也**不隐式读取系统或环境代理变量**；不会把未勾选的来源悄悄改走代理。
- **失败语义**：代理不可达或代理地址非法只让**当前候选**失败，按现有自动回退尝试其它候选；**失败后不会偷偷直连，也不静默降级**。代理配置错误属于后端故障，不折叠成客户端 4xx。
- **一致性**：推理请求、模型目录拉取与 **Chat → Responses** 桥接使用同一策略；连接器自带的上游出站（含 OAuth 与令牌刷新，若有）同样按该策略出站。连接器自带的本地通道（如 `127.0.0.1` 管理接口）**恒为直连**，不受代理影响；「连接」按钮在系统浏览器打开的授权页由浏览器自行走系统代理，不经本扩展。
- **本机回环上游**：连接器本地通道恒直连（上一条）；但若某个**被勾选走代理的原生供应商**其上游本身是本机回环（`127.0.0.1`），CFNetwork 对回环目标在 `https` / `socks5` 代理下会**绕过代理**、无法按预期出站，此时应用**明确报错并要求取消勾选该供应商**，既不静默直连也不静默绕过代理。
- **系统要求**：`http` / `socks5` 代理 macOS 13 起可用；`https://`（**与代理之间**走 TLS，TLS-to-proxy）需要 **macOS 14 或更高**——在更低系统上保存/启用该地址会按配置错误提示，**不降级直连**。目标上游是否为 HTTPS 与此无关。
- **代价**：修改代理（开关、地址或名单）会重启受影响的连接器组件，**可能中断进行中的工具会话**。
- **生命周期**：连接器来源按稳定 `source` 保存（账号级、登录前即可选），与供应商名解耦；删除某个原生供应商只清理它自身在**原生**名单（`providerNames`）里的选择，**不**清除连接器来源的出站选择（`connectorSources`）。

## 实现范围

扩展随应用内置。Chat → Responses 通过每请求独立的桥接进程执行；出站代理不常驻运行，只在转发时按策略选择出站会话。两者都不支持第三方扩展安装、热加载或插件市场。

扩展在主干中通过通用注册表与运行时接入：`ExtensionRegistry` 负责请求转发、模型目录与支持协议，`ExtensionRuntime` 负责启动与刷新。连接器框架仍保留，但当前**没有内置连接器**：可选连接器的实现会集中在各自 `Extensions/<连接器>` 目录，主干仅由 `BuiltinExtensions.swift` 这一组合点指名。出站代理是当前唯一的可选扩展：出站能力由通用 `OutboundPolicy` 接口承载，扩展本体集中在 `Extensions/Proxy`，只经 `BuiltinExtensions.swift` 组合，原生供应商按名勾选，并保留按 `source` 勾选连接器来源的能力（当前无连接器可列）。出站代理可在构建时以 `EZSWITCH_DISABLE_PROXY=1` 整体排除，移除只需删除其目录与组合注册。这**不**构成独立 SwiftPM 模块或二进制隔离；Chat → Responses 暂保留现有共享配置与执行。完整分层、持久化兼容契约与可复现检查命令见[扩展架构与移除说明](extension-architecture.md)。
