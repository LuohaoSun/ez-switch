# Native API audit

Scope: use Apple framework interactions for the app's sidebar, cards, model dragging, multi-selection and windows. All suitable opportunities from the original audit are now implemented. Routing and transport rules remain app-specific logic.

## Implemented

| Area | Native implementation | Availability and behavior |
| --- | --- | --- |
| Sidebar | macOS 14+: `NativeSettingsSplit` (`NSViewControllerRepresentable` over `NSSplitViewController`); macOS 13: `NavigationSplitView`, `List(selection:)` and a visibility binding | macOS 14+ uses `NSSplitViewItem(sidebarWithViewController:)` with min/ideal/max 170/190/240, holding priority 450, `canCollapseFromWindowResize = false` and `collapseBehavior = .preferResizingSiblingsWithFixedSplitView`, and `NSHostingController.sizingOptions = []` so pane content cannot inflate the constraint budget. The split fills the full window height and publishes real titlebar safe areas (`detailItem.automaticallyAdjustsSafeAreaInsets` on macOS 26+). macOS 13 keeps `NavigationSplitView` because `NSHostingController.sceneBridgingOptions` is unavailable there, so the activity toolbar/search would not bridge across the AppKit hosting boundary. `List(selection:)` provides native selection and keyboard navigation. |
| Workspace panels | `NSSplitView` via `NSViewRepresentable` (`NativeWorkspaceSplit`) | Native thin divider adjusts supplier and route widths while preserving minimum usable widths. Both hosting views set `sizingOptions = []`, so their content cannot push the surrounding layout. |
| Card expansion | `DisclosureGroup(isExpanded:)` | Native disclosure and accessibility semantics retain rounded card styling. Management menus and automatic-fallback toggles sit outside the disclosure trigger. Collapsed routes retain a current-model summary. |
| Model transfer | `ModelDragItem: Codable, Transferable`, native `onDrag` and typed `dropDestination` | macOS 13+. NSItemProvider registers the Transferable directly; no string parsing is used. Model drags do not register container item IDs, preventing the card reorder container from interpreting them as card moves. The payload contains only a model UUID. |
| Model selection | Checkbox `Toggle` in model-list rows | Both new-provider onboarding and existing-provider catalogs use the same native checkbox control. Independent single-click multiple selection is preserved. |
| Settings window | SwiftUI `Window(id:)` and `openWindow` | macOS 15+. Default launch is suppressed and restoration disabled, preserving silent login-item launch. macOS 13–14 retain native AppKit NSWindow/NSHostingController because scene launch suppression is unavailable. AppKit activation policy coordination remains necessary for a menu-bar app. A standard app-menu panel command supports Command-comma. |
| Log byte sizes | `ByteCountFormatter`, binary count style | Foundation handles localized units and precision. |

## Card and model dragging

`NativeReorderableCards.swift` uses `ForEach.reorderable()`, `dragContainer`, `reorderContainer`, and header-only `draggable(containerItemID:)` on macOS 27+. The ForEach element, drag payload, and reorder container use the same identifiable wrapper type. Only its ID is exported. The system owns placement previews and drag animations; move callbacks persist through ConfigStore.

macOS 13–26 uses native `List` / `ForEach.onMove`. The deployment target remains macOS 13. No handwritten card DropDelegate, temporary display order, hover sorting, or drag-provider deinit cleanup remains.

Model transfer uses system plain-text Codable transport restricted to the app process. CoreTransferable handles encoding and decoding; no NSString loading or manual UUID parsing is used. Membership checks, same-provider restrictions and route insertion rules remain application logic. Model sources use `onDrag` with `NSItemProvider.register(item)`, outside the container-item mechanism used for card reordering. Card identity is a dedicated `CardReorderID`, distinct from model UUID identity. Earlier nested model drag containers passed limited preview checks but failed actual user testing, so they have been removed. Additional hover-state redraw is not installed because it interrupted drop completion in the current SwiftUI environment.

The default settings window is 1120 × 760, with a 1000 × 640 minimum. The supplier panel starts at 280 points and is adjustable within 220–300 points; the route panel takes the remaining width, with roughly 20 points of outer margin. Flexible zero-minimum frames constrain card content to available width. Long model labels truncate inside their row, preserving action buttons. On macOS 14+ the sidebar is a native `NSSplitViewController` split (`NativeSettingsSplit`): `collapseBehavior = .preferResizingSiblingsWithFixedSplitView` keeps the split geometry stable, hosting sizing is disabled, and the split fills the full window height with real titlebar safe areas, so hiding or showing the sidebar resizes the panes while the outer window width stays fixed. macOS 13 falls back to `NavigationSplitView`. The model-ID lookup is constructed once per route panel evaluation instead of rebuilding it for every candidate.

## Already native or retained

- Login items use SMAppService; Finder reveal and opening files use NSWorkspace; copying uses NSPasteboard.
- Configuration uses FileManager and a DispatchSource filesystem watcher. Updates use URLSession, CryptoKit SHA256 and NSWorkspace.
- MenuBarExtra, the log Window scene, standard About panel and NSAlert are native. AppKit activation notifications and regular/accessory policy transitions remain required.
- Log polling uses native Timer, and current-model labels use TimelineView. Event-driven updates would be an update-design change rather than a native API replacement.
- Forwarding uses URLSessionDataDelegate to bridge chunks to NIO with explicit redirect and cancellation behavior. URLSession.bytes(for:) is not a drop-in replacement for this transport.
- Routing, fallback policy, harness configuration, Responses/Chat translation and GitHub release/checksum policy have no equivalent Apple framework feature.

## Verification and limits

- The routing/transport business-logic suite passed 109 Swift tests in 19 suites, including a check that card identity is distinct from model identity and cannot decode as a model payload. This suite covers logic only, not window geometry. Debug and Release builds succeeded.
- Correction GUI checks used `/tmp/EZSwitch-LayoutFix.app` on port 18996 with 8 dummy suppliers, 24 long-named models and 3 routes. At the 1120 × 760 default size, the sidebar, copy/add controls and card actions were visible without horizontal clipping; the supplier panel measured 300 points. These settled-state checks did not exercise a user-widened sidebar and therefore missed the outer-sizing regression noted below.
- Model moves toward the beginning and end of candidate lists committed while retaining the selected model and route-card order. Separate header dragging still reordered cards. Supplier-to-route dragging added a candidate. Config comparison verified that a model-only move changed candidate order without changing supplier records, fallback switches or selected models.
- Three sidebar hide/show cycles completed with the supplier width staying at 300 points. This was a settled-state-only check and did not catch the outer-sizing regression: when the user widened the sidebar, the `NavigationSplitView` root transiently re-proposed a larger width to its detail (1120 → 1360) and fed it back into the window, which expanded and snapped back. This is not a measured animation frame rate.
- Latest diagnostic root invariant: with the native `NSSplitViewController` split, the outer window stayed 1120 points wide across all six sidebar hide/show actions, with no AutoLayout unsatisfiable-constraints warnings and a single titlebar safe-area application (no duplicate 52-point overlay). This asserts a settled root-geometry invariant, not an animation frame rate.
- Full-height Debug preview `/tmp/EZSwitch-*.app` (port 18997, 8 providers, 24 models, 3 routes) kept the outer split at 1120 points across three sidebar hide/show cycles, with a 20-point right margin.
- Window width coverage on the same preview: 1000 × 760, 1120 × 760, 1401 × 1066 and 1800 × 1066 all stayed bounded with a 20-point right margin.
- A 239-point sidebar (near the 240 maximum) combined with a 1000-point window width passed two collapse/reveal cycles. The supplier divider reached both the 300- and 220-point limits while the window width stayed at 1000 points and the action buttons remained visible.
- Candidate reordering, a cross-pane provider-3 model added to `ultra`, a route-card move of `main` above `ultra`, and a same-provider move of `gpt` to the top all committed. `/tmp/ezswitch-check-layout-fixture.py` data comparisons confirmed that selection, fallback and model records were preserved and that card moves only reordered cards.
- The supplier add sheet opened and cancelled; the General pane navigation displayed intact; the Activity pane title/header plus pause/copy/search toolbar were visible, and pause toggled the header state. No `LogWindowView` source changed.
- Log filtering is not claimed as verified: GUI typing (accessibility and event/coordinate fallback) never focused or entered the field, and `setValue` changed the native text without updating the model, so search behavior remains an automation acceptance limit.
- Earlier migration verification passed 108 Swift tests in 19 suites, including an NSItemProvider/CoreTransferable round trip asserting that model payloads contain only the UUID. Debug and Release configurations built successfully. The independent `dist/EZSwitch-NativeInteractions.app` bundle passed deep strict ad-hoc signature verification.
- The Release preview opened successfully with persisted supplier and route ordering. A route-card move committed, and comparing records by route ID before and after confirmed every route field—including candidates, selection and autoFallback—was unchanged.
- GUI checks used a separate `/tmp/EZSwitch-InteractionsPreview.app`, dummy supplier credentials, its own configuration and port 18994. The production service on port 8788 was preserved.
- On macOS 27.2, native sidebar navigation and hide/show worked. The workspace divider moved from 635 to 550 in the accessibility state, and both panels resized.
- Supplier and route cards reordered and persisted. Restarting the preview retained ordering. Model dragging into routes, candidate insertion and supplier-internal model sorting succeeded. Candidate sorting retained the selected model. Cross-provider model sorting was rejected without changing supplier membership.
- Card disclosure worked, and collapsed routes showed the current model. Independent automatic-fallback controls and management menus did not serve as disclosure triggers.
- Existing-provider catalog checkboxes supported multiple checked models. Selecting an existing model plus a new model added only the new entry. New-provider onboarding uses the same control but was not separately exercised end to end.
