# 活动

侧栏「活动」是运行期内的实时视图，由顶部流向图与下方请求表组成，每秒刷新。它只在本机展示转发过程，数据不写入磁盘。

## 可视化

- **流向图**：左侧是客户端请求（按入站协议与路由命名），中间是 EZSwitch，右侧是实际命中的上游（供应商 · 模型）。同一请求左右两段连线同色，进入完成驻留时保留原颜色。
- **请求表**：每行以协议胶囊标示入站协议（Chat / Responses / Messages / Gemini），其后是时间、API 类型、路由、上游模型、状态、输入／输出 token 与耗时（窄窗口先隐藏时间与耗时）。
- **展开详情**：点击行展开该请求的缓存命中、缓存写入、推理、首字（真实 TTFT）与回退链，以及用量覆盖说明（哪些尝试未上报用量、表中 token 来自第几次尝试）。
- **点击仅高亮**：点击图上的请求或上游节点只高亮该节点及其关联连线与请求行，再次点击取消；列表内容只由搜索词决定，不因高亮增删行。搜索匹配短 ID、路由、协议、供应商或模型。

## 在途与已完成

- 进行中的请求与已完成的请求分开保存：**在途请求不受上限淘汰**，已完成的请求只保留**最近 300 条**，超出的按最早淘汰。
- 已完成（成功／失败／取消）的请求不会立刻离开流向图，自真实结束时刻起**驻留 5 秒**，便于看清去向与最终状态；驻留时长不随刷新延长，暂停时快照冻结、节点也不会提前消失。
- 图上最多同时展示前 6 个节点（在途优先），其余以文字提示“另有 N 条请求未在图中展示”；中间节点分别统计在途与刚结束的条数。

## 口径与隐私

- 该结构化活动存储只保存元数据：**不含请求／响应正文、API Key、Base URL 或查询串**，不从原始日志恢复历史。
- 状态只陈述快照已观测到的阶段：「接收响应」表示已开始转发上游响应字节（可能是 SSE 心跳或仅含角色的帧），**不代表首字内容已到**；首字延迟取真实 TTFT 采样，不用首个字节代替。
- 耗时取单调时钟实测，与系统时钟跳变无关；未报告的字段显示「—」，不伪造 0。
- 数据只存在于本次运行的进程内，退出应用即清空；暂停只冻结展示，恢复后取到最新状态。
